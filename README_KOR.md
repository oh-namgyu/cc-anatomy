# cc-anatomy

[![CI](https://github.com/oh-namgyu/cc-anatomy/actions/workflows/ci.yml/badge.svg)](https://github.com/oh-namgyu/cc-anatomy/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

*(English: [README.md](README.md))*

Claude Code가 사용자의 입력을 어떻게 처리하는지를 보여주는 인터랙티브 개념 모델입니다.
각 레슨은 직접 조작할 수 있는 흐름 다이어그램입니다. 입력 조합을 고르면 해당 시나리오가
다이어그램 위에서 단계별로 재생되고, 매 스텝마다 설명이 붙습니다. 입력을 바꾸면 다른
경로에 불이 들어옵니다.

네 개의 레슨이 에이전트 루프·슬래시 명령·훅·스킬을 다룹니다. 모든 레슨의 모든 스텝은
공식 문서의 한 줄까지 추적할 수 있습니다.

정적 사이트입니다 — 빌드 스텝 없음, 서버 없음, API 키 없음, 계정 없음.

---

## ⚠️ 비공식 프로젝트

**비공식 커뮤니티 프로젝트입니다. Claude Code의 *문서화된 동작*에 대한 개념 모델이며,
실제 구현이 아니고 Anthropic과 무관합니다. 내용은 2026-08 기준 공식 문서에 근거하며,
스텝별 인용 대조표는 [docs/CONTENT-REVIEW.md](docs/CONTENT-REVIEW.md)에 있습니다.**

문서가 순서를 명시하지 않은 지점에서는 다이어그램도 순서를 지어내지 않습니다 — 그런
요소들은 "순서 없는 묶음"으로 그리고 그렇게 라벨을 답니다. 동작 자체가 문서화되어 있지
않은 경우에는 추측 대신 해당 스텝에 `undocumented` 배지를 답니다.

## 실행해 보기

**라이브 데모:** https://cc-anatomy.vercel.app

**로컬 실행** — 클론한 뒤 정적 파일 서버로 디렉토리를 서빙하면 됩니다:

```bash
git clone https://github.com/oh-namgyu/cc-anatomy.git
cd cc-anatomy

python3 -m http.server 6182     # http://127.0.0.1:6182 접속
# 또는
npx serve .
```

`index.html`을 파일로 직접 여는 방식은 **동작하지 않습니다**. 앱이 ES 모듈이라
브라우저가 `file://` 에서의 모듈 로드를 거부하기 때문입니다. 어떤 정적 서버든 상관없습니다.

## 레슨

| # | 레슨 | 소요(분) | 조작하는 입력 |
| :-- | :--- | :-- | :--- |
| L1 | 에이전트 루프 | 6 | 작업 종류(질문 / 편집) × `CLAUDE.md` 없음 또는 있음 |
| L2 | 슬래시 명령 | 5 | 명령 본문의 `$ARGUMENTS` 유무 × 인자 전달 여부 |
| L3 | 훅 | 8 | 설정된 훅(off / PreToolUse / PostToolUse / Stop) × 종료 코드(0 / 2) |
| L4 | 스킬 | 5 | 호출 주체(사용자 / 클로드) × 프론트매터(기본 / `disable-model-invocation`) |

각 레슨 말미에 세 문항의 퀴즈가 있습니다. 세 문항을 모두 답하면 레슨이 완료로 표시되며,
진행도는 `localStorage`에 저장되어 브라우저 밖으로 나가지 않습니다.

L3에서 종료 코드 분기를 일급 입력으로 둔 이유가 있습니다. **`exit 2`는 하나의 의미가
아닙니다.** `PreToolUse`에서는 도구 호출을 차단하고, `PostToolUse`에서는 stderr를 클로드에게
되돌려 주며, `Stop`에서는 계속 진행하도록 강제합니다. 이 각각을 하나의 단순화된 "차단"으로
뭉뚱그리지 않고 별도 시나리오로 재현합니다.

## 내용 정확성을 어떻게 담보했나

레슨은 코드로 쓰이기 전에 문서로 먼저 쓰였고, 검수는 그 사이에 이루어졌습니다.

1. **스펙 먼저** — [`docs/CONTENT-SPEC.md`](docs/CONTENT-SPEC.md)가 모든 다이어그램 노드,
   모든 분기, 127개 시나리오 스텝 전부를 산문으로 확정합니다. 레슨 데이터 모듈이 하나도
   존재하기 전 단계입니다.
2. **인용 대조 검수** — [`docs/CONTENT-REVIEW.md`](docs/CONTENT-REVIEW.md)가 스텝마다 한 행을
   부여합니다. 각 행에는 그 스텝이 주장하는 내용, 근거가 되는 공식 문서 페이지, 그리고 그
   페이지에서 발췌한 **원문 인용**이 들어갑니다. 게이트는 "URL이 존재하는가"가 아니라
   "그 발췌가 정말 그 스텝의 내용을 말하는가"입니다. 총 135행이며, 그중 21건은 검수를
   통과하지 못해 구현 전에 서술이 수정되었습니다.
3. **독립 교차 검수** — 별도의 검수자가 쟁점 영역(이벤트별 exit 2 의미, `stop_hook_active`,
   `PreToolUse`의 exit 0이 승인이 아니라는 점, 스킬/명령 우선순위)을 저자의 결론을 전달받지
   않은 상태에서 실시간 문서 조회로 재검증했습니다. 결과는 지적 0건이며 검수 파일 하단에
   기록되어 있습니다.
4. **그다음에야 데이터** — 레슨 모듈은 검수를 마친 스펙을 옮겨 적은 것입니다. CI의 스키마
   게이트가, 존재하지 않는 다이어그램 노드를 참조하는 스텝이나 시나리오가 커버하지 않는
   입력 조합이 남은 레슨을 거부합니다.

각 레슨은 `sources`(화면에서 "Learn more" 링크로 노출)와 화면에 표시되는 `asOf` 기준일을
함께 갖습니다.

**정정 정책.** Claude Code는 변합니다. 레슨은 데이터이므로 정정은 데이터 수정 + 재배포로
끝납니다. 공식 문서가 더 이상 뒷받침하지 않는 스텝을 발견하면 문서 URL과 해당 발췌를 담아
이슈를 열어 주세요. 그것만으로 수정에 충분합니다.

## 비슷한 프로젝트

이것이 유일한 인터랙티브 Claude Code 학습 도구는 아니며, 그런 것처럼 말하는 것은 정직하지
않습니다. 함께 볼 만한 선행 작업들입니다.

- [**claude-code-visualizer**](https://github.com/jonwiggins/claude-code-visualizer)
  — 에이전트 루프를 인터랙티브 플로우차트로 시각화하고, 시나리오 워크스루와 권한 모드·훅을
  토글하는 샌드박스 패널을 제공합니다.
- [**claude.nagdy.me**](https://claude.nagdy.me) — 브라우저 터미널 시뮬레이터와 퀴즈를 갖춘
  12개 인터랙티브 모듈.
- [**claude10x.com**](https://claude10x.com) — 슬래시 명령·메모리·스킬·서브에이전트·MCP·훅을
  아우르는 30개 레슨 인터랙티브 코스.

cc-anatomy가 다르게 하는 지점을 있는 그대로 적으면 이렇습니다.

- **다이어그램 위에서의 입력 조합 분기.** 입력은 값이 열거된 위젯 집합으로 선언되고, 그
  데카르트 곱의 **모든 조합**이 각각의 시나리오에 매핑되어야 합니다 — 스키마 게이트가
  강제하므로 분기가 소리 없이 빠질 수 없습니다. 미리 만들어진 시나리오를 목록에서 고르는
  것이 아니라, 입력을 설정하고 그 결과로 어떤 경로가 나오는지를 보는 방식입니다.
- **EN/KO 이중 언어가 전면 적용됩니다.** 인터페이스만이 아니라 모든 스텝 설명·배지·퀴즈
  문항과 선택지가 두 언어로 존재하며, 스키마가 이를 검사합니다.
- **스텝별 인용 대조표가 커밋된 산출물로 존재합니다.** 원문 발췌를 포함해 독자에게 공개되며,
  "정확합니다"라는 내부 주장으로 갈음하지 않습니다.
- **문서가 말하지 않은 순서를 단정하지 않습니다.** 문서화되지 않은 순서는 순서 없는 묶음으로
  그리고, 문서화되지 않은 동작에는 그렇다고 명시하는 배지를 답니다.

넓이 대신 깊이를 택한 트레이드오프입니다 — 여기는 4개 레슨, 다른 곳은 12개 또는 30개.

## 개발

```bash
npm ci                                  # dev 의존성: @playwright/test 하나뿐
npm test                                # node --test — 스키마 게이트 + 레슨 데이터
npx playwright install chromium         # 최초 1회
npx playwright test                     # python3 정적 서버 대상 e2e
```

런타임 의존성은 0입니다. 페이지는 외부 호스트에서 아무것도 로드하지 않습니다 — CDN 스크립트,
웹폰트, 애널리틱스 전부 없으며, `default-src 'self'` CSP meta 태그로 강제합니다. 외부로
나가는 것은 공식 문서로의 `<a href>` 링크뿐입니다.

**레슨 = 데이터 모듈.** `js/lessons/*.js`는 순수 객체를 export하고, 엔진(`js/engine/`)은
스키마를 통과하는 어떤 객체든 렌더링합니다. 레슨 추가는 파일 하나 추가 + `js/lessons/index.js`에
한 줄 추가이며, 엔진은 손대지 않습니다. 스키마 형태·검증기 오류 코드·인용 규칙은
[CONTRIBUTING.md](CONTRIBUTING.md)를 보세요.

`node scripts/shots.mjs` 로 위 스크린샷을 재생성합니다.

## 로드맵

- **L5 — 서브에이전트**: Agent 도구를 통한 위임, 백그라운드 완료 알림.
- **L6 — 권한**: allowlist 매칭과 plan 모드 게이트.
- **스크린리더 대응**: 현재의 키보드 조작·`prefers-reduced-motion` 지원을 넘어, 스텝 변경을
  읽어 주는 live region 추가.
